# Core Principles / 当前核心原则

## 证据驱动、结构确认、风险优先、保留判断

BSHL帮助研究者连接投研假设、证据、定价判断、日线结构与风险门控。它不保证超额收益。产业链、市场环境与估值研究由人工提供来源和评分，不能把模板文字当成已联网的分析。

1. **来源与时点先于结论。** 记录URL、发布时间、可用时间、支持/反对及可选失效时间。未来和过期证据不得支持当前准备状态。来源是否真实仍需核验；官方文件的标签不能替代真实性检查。没有强支持证据时保持研究，不生成虚假分数。
2. **确定性代码决定结构和门控。** 使用[数据合同与公式](../docs/DATA_CONTRACT.md)。母周期必须完成，pivot必须等待右侧确认，止损由用户选择，不能自动采纳建议价。初始执行范围仅为US/USD日线股票/ETF现金做多。
3. **必要条件不能被软分补偿。** 非模拟数据、支持的交易所/配置、收盘与结构确认、完整风险检查、有效止损/目标、RR>=2、Trade分>=85及足够研究证据同时满足，才评估Trade Ready。行情过期与未知项明确阻断。
4. **风险有明确优先级。** 流动性、波动、止损距离或监管检查失败为Veto；弱证据为Watch Only；财报风险/价格位置失败为Wait；缺检查为Wait Confirmation；拥挤、已有敞口或相关性失败为Reduce Size。顺序以[风控实现](../scoring/risk_governor_score.py)为准。engine中的量化阈值见数据合同；不沿用旧页面不同的ATR阈值。
5. **模拟与真实判断分开。** Mock的final_status始终Research Only，simulation_status可以展示规则拒绝或准备结果。模拟Veto仍是模拟门控结果，不能解释为真实资产判断。
6. **原判断不得按结果改写。** 快照、用户决定与后来的结果分开保存。使用[本地工作区](../docs/WORKSPACE.md)记录新卡、条件变化、事件复核和带时间的结果。漏掉上涨不证明风险规则错误。
7. **进化先做候选与验证。** 候选记录保留样本来源、配置对比与人工批准；批准只用于新的保留样本评估。硬风控不自动删除，候选不自动改变评分器。小样本不能证明策略有效。

## 输出状态

Research Only：仅研究；Watchlist：观察并补条件；Trade Ready：经门控的研究准备；Wait Pullback：兼容旧命名的等待状态，也可能因财报等风险等待；Avoid：准备条件不合适；Veto：硬风险否决。
Trade子评分状态与统一final_status是不同层次；不要把子评分的Trade Ready直接当成最终批准。所有状态都不是订单。

各层分数和分项可供解释，但不得称为上涨概率或“多少分即可买入”。[模拟报告](../docs/BACKTEST.md)检验机械流程，不重建历史LLM投研，不认证盈利优势。
